# Security design

This page maps each protection in Flight Check's bundled script to the code that implements it and the tests that check it. Paths are relative to `plugins/flight-check/scripts/flight_check_lib/` for code and `tests/unit/` for tests.

| Protection | What it does | Code | Tests |
|---|---|---|---|
| No network, no subprocess | The script uses only the Python standard library and never opens a network connection or runs another program. | Enforced on every commit by `tools/lint_plugin.py` (`FORBIDDEN_MODULES`, `FORBIDDEN_CALLS` such as `eval`, `exec` and `__import__`, and `os` process calls) | The lint runs in CI |
| What leaves your machine | Nothing, from the script. The agents' reads go to your Claude Code session's model provider, like any other Claude Code task. Flight Check adds no telemetry. | README, "Privacy and data handling" | — |
| Secret masking | Likely secrets (cloud, GitHub, Slack, Stripe and model-provider keys, private keys, JWTs, password and token assignments) are replaced with `[REDACTED]` in everything written from agent results: `report.md`, `audit.final.json`, the ledger, and Attorney Review Packets. Placeholders such as `${DB_PASSWORD}` are left alone. Masking is pattern-based and can miss unusual formats. | `textsafety.redact`, `assemble.mask_secrets` | `test_textsafety_evidence.py`: `test_redacts_known_secret_formats`, `test_placeholders_are_not_redacted` |
| Owner-only local files | Each run directory, and the `runs/` folder when Flight Check creates it, is mode 0700. Files the script writes are created through `tempfile.mkstemp`, so they are mode 0600. Run directories are gitignored automatically. | `cli.cmd_init_run`, `jsonio.dump_json` | `test_end_to_end.py`: `test_init_run_and_ledger_cli` |
| State integrity | Every command that changes state (the ledger, `project.json`, `registers.json`) holds one lock (`state.lock`) from reading to writing; a lock left by a crash is removed after 10 minutes. Files are schema-checked on load and before every write, written atomically, and journaled so an interrupted command can be rolled back (`state recover`). Every change appends a hash-chained event to `history.jsonl`, so edits to the log are detectable (`state check`); this detects tampering but cannot prevent it. Symbolic links are refused for the state directory and its files. State from another project is refused (runs carry the project ID, and the project's location in its repository is checked). | `lockfile.locked`, `state.transaction`, `state.load`, `state.recover`, `state.check_identity` | `test_state.py`, `test_ledger_gate.py`: `LedgerLockTests` |
| Retention | Run directories and packets stay on your disk until you delete them; Flight Check has no automatic cleanup and keeps no copies elsewhere. The ledger keeps finding history (titles, locations, decisions), not raw agent replies. | README, "Privacy and data handling" | — |
| Path containment | Cited files must resolve inside the audit root; `..` paths and symlinks that leave the root are refused. Entry-point paths in the inventory must be relative and stay inside the root. | `evidence.resolve_within`, inventory schema | `test_textsafety_evidence.py`: `test_missing_file_and_out_of_root`, `test_symlink_escaping_root_is_refused`; `test_validation.py`: `test_entry_point_files_must_stay_inside_the_audit_root` |
| Output encoding | Text from audited files and agents is treated as data. Markdown output escapes HTML, neutralizes links and images, and escapes table and heading characters; code blocks use a fence longer than any backtick run in the content. PDF text strings escape `\`, `(` and `)`. | `render_md.md`, `render_md.code_block`, `pdf._escape` | `test_textsafety_evidence.py`: `test_markdown_neutralizes_links_images_and_html`, `test_code_block_fence_longer_than_content` |
| AI data boundaries | Flight Check runs for one user on that user's machine. There is no shared service, so one user's project never enters another user's model context. Audit agents can only read (Read, Grep, Glob); they have no network, shell, or write tools, so text in an audited file cannot make them send data anywhere. The skills pre-approve only `flight_check.py` subcommands, which make no network connections; any other command asks the user unless the user's own settings allow it. Audited files, including any secrets in them, do enter the model context and go to the user's model provider under the user's Claude Code configuration. That provider's retention and training terms are outside this repository; see the README, "Privacy and data handling". | `plugins/flight-check/agents/*.md` (`tools: Read, Grep, Glob`), `skills/*/SKILL.md` (`allowed-tools`); both checked by `tools/lint_plugin.py` | The lint runs in CI |
| Change detection | What changed is decided by content hashes, never timestamps. The scan never follows symbolic links and skips version-control, Flight Check, dependency, and build directories. It stops at 200,000 files and compares files over 50 MB by size only; a stopped scan, a missing or unreadable file list, or a change no rule explains widens reassessment to every applicable domain instead of narrowing it. | `freshness.scan`, `freshness.changes` | `test_freshness.py`, `test_hardening.py` |
| Audits of changes only | A domain is carried forward only when nothing changed since the last run affects it. Finalize re-checks the run's `scope.json` against the files, so a tampered or outdated scope can only reduce what is carried forward; a malformed scope stops finalize. A malformed `files.json` is ignored. Carried-forward controls whose cited files changed become UNVERIFIED, and carried-forward findings still count. | `finalize._scope`, `finalize.finalize`, `assemble._carried_control` | `test_freshness.py`: `IncrementalTests`; `test_hardening.py` |
| Report output | `status` and `report` only read. With `--out` they write a file name, without directories, under `.flight-check/reports/` and refuse symbolic links, so a pre-approved command cannot overwrite another file. Markdown output uses the same escaping as reports. | `cli._emit_view`, `status.render_markdown` | `test_status.py`: `test_every_view_renders_and_writes` |
| Records as data | Decision assertions are passed to agents as statements to check, never as instructions; a contradiction counts only as an evidence-backed finding, and Flight Check never changes a decision. Record text that quotes the project is treated as data by the status skill. | `registers.apply_decision_conflicts`, `skills/status/SKILL.md` | `test_status.py`: `DecisionConsistencyTests` |
| Release check | `release-check` only reads. It lists tracked files by reading git's index file itself (no git process, size-limited, malformed or sparse indexes rejected) and hashes only regular files inside the checkout, skipping absolute and `..` paths. GitHub annotations escape their text. It is a process control: the committed records it trusts can be edited by anyone who can commit, which the hash-chained history makes visible but cannot prevent. | `release.py`, `cli.cmd_release_check` | `test_release.py` |
| Watch mode (hooks) | The plugin's three hooks (session start, after an Edit or Write, and when Claude stops) run only `flight_check.py hook <event>`; the lint pins `hooks/hooks.json` to exactly those commands with a timeout of at most 30 seconds. Each hook reads local files only, prints nothing unless the project's local `.flight-check/watch.json` turns watch mode on, never fails the session (errors mean no output, and the command ends with `|| true`), and never starts an audit. Its notes to Claude never repeat a secret's value; test directories are skipped. `watch.json` and `reminders.json` are gitignored. | `watch.py`, `hooks/hooks.json`, `tools/lint_plugin.py` (`check_hooks`) | `test_watch.py` |
| Skills Claude may start | Only `start` (read-only), `status` (read-only apart from the user's local preferences, when asked), `fix` (asks the user once before changing anything, records each fix, starts no paid audit), and `legal-packet` (builds a document; records how the user sorted each legal question only from the user's answers, and each record needs the user's confirmation, since `legal update` is never pre-approved). Audits, remediation with re-audit, watch mode, and other decisions only the user can make stay manual. | `tools/lint_plugin.py` (`MODEL_INVOCABLE_SKILLS`), `skills/*/SKILL.md` | The lint runs in CI |
| Pre-approved file writes | The audit skill may write without a prompt only inside its own run directory (`Edit(./.flight-check/runs/**)`), for `run.json`, `summary.json`, and agent replies; it can never edit project files (its `Edit` tool is disallowed, and every other write still asks). The lint rejects any other pre-approved write in any skill. | `skills/audit/SKILL.md`, `tools/lint_plugin.py` (`RUN_DIR_WRITES`) | The lint runs in CI |
| SARIF export | `sarif` only reads the ledger. It exports only findings whose path is a regular file inside the audit root (no absolute, `..`, or linked paths), percent-encodes paths, and with `--out` writes only a file name under `.flight-check/reports/`, refusing symbolic links. Finding titles were already masked for secrets when recorded. | `sarif.py`, `cli.cmd_sarif`, `cli._report_file` | `test_sarif.py` |
| Evidence check | Every quoted line is compared with the cited file before a finding is accepted. | `evidence.py` | `test_textsafety_evidence.py` |
| Limited permissions | Agents are read-only (Read, Grep, Glob). Skills pre-approve only the script subcommands they need; decision commands always ask. | `plugins/flight-check/agents/*.md` and `skills/*/SKILL.md`; checked by `tools/lint_plugin.py` | The lint runs in CI |

Releases and rollback are described in [maintainers/releasing.md](maintainers/releasing.md). For code you do not own or trust, see [hardened-mode.md](hardened-mode.md). To report a vulnerability in Flight Check, see [SECURITY.md](../SECURITY.md).
