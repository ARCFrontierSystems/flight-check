Two Flight Check 1.5 audits of this repository, both with `--passes 2` and the CI vulnerability-scan output and local check results imported as evidence:

- **Run 1** (`20261013T050120Z`, about $3.59): a full audit. It was the first 1.5 command on this repository, so it also migrated the 1.0 ledger.
- **Run 2** (`20261013T051206Z`, about $3.80): `--changed`, after fixing what run 1 found.

The purposes were to check the release candidate, and to try the migration and an audit of changes on a real project.

## 1.5 features on a real project

- **Migration from 1.0.** Run 1's finalize migrated the ledger as documented:
  - it backed up the 1.0 ledger;
  - it moved 25 findings and 12 legal items to schema 2.0;
  - it created `project.json`, `registers.json`, and `history.jsonl`.

  `state check` passed after both runs.
- **Audit of changes.** Run 2 found 12 changed files since run 1.
  - It reassessed 12 domains and carried forward 5: infrastructure, reliability, operational readiness, production readiness, and AI/LLM.
  - Two carried-forward findings, FC-0001 (accepted risk) and FC-0027, still counted in the ship decision.
  - The inventory reported infrastructure not applicable, while the stored state carried it forward. Flight Check kept the carried-forward result and noted the conflict.

## Tool problems found and fixed

1. **Backup name masked.** The high-entropy secret rule masked backup directory names, which contain a timestamp such as `20261013T050120Z`. That made the migration message unreadable. A timestamp part is now treated as a word.
2. **Git worktree file seen as a change.** In a git worktree, `.git` is a file rather than a directory. The file list hashed it, and every audit of changes saw it as an unexplained change and widened to every domain. Change detection now skips `.git` and `.hg` files. A baseline entry under a path the scan now skips is ignored, rather than reported as deleted.
3. **Migration test used this repository's ledger.** Once this repository's ledger moved to 2.0, the 1.0 migration test had nothing to migrate. It now uses a fixed 1.0 ledger in `tests/fixtures/`.

## Limitations

- Which release-critical control lacks positive evidence varies between runs: the agents and the verifier are language models. Repeat passes reduce this variation but do not remove it.
- Two audits of one repository. They exercise the 1.5 features, but they are not an evaluation.

This record reflects only the evidence examined. It is not a certification or legal advice.
